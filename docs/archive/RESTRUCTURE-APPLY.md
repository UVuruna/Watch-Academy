```bash
cd Applications/WatchAcademy
git fetch <worktree-remote-or-path> three-folder-migration
```

Everything under git tracking — `desktop/`, `shared/`, `android/`, and the
root docs — arrives with full history (every move was `git mv`, never
delete+recreate).

## 4. `DOMYWatch.spec` (gitignored, untracked, present only on the real
tree — confirmed: `Applications/WatchAcademy/DOMYWatch.spec` exists today)

Its `Analysis(['main.py'], datas=[('Database','Database'),
('assets','assets')], ...)` must become:

```diff
 a = Analysis(
-    ['main.py'],
+    ['desktop/main.py'],
     pathex=[],
     binaries=[],
-    datas=[('Database', 'Database'), ('assets', 'assets')],
+    datas=[('shared/Database', 'Database'), ('shared/assets', 'assets')],
```

and PyInstaller must be invoked from the repo root (not from `desktop/`) so
these relative `datas` paths resolve. `config.paths.app_root()` already
handles the frozen case unchanged (`sys._MEIPASS` still holds `Database/`
and `assets/` directly, since that's what the `datas` tuples' SECOND
element controls) — only the spec file's SOURCE paths (the first element
of each tuple, and the `Analysis(['main.py'])` entry point) need the
`desktop/`/`shared/` prefix.

## 5. HKCU Run key (autostart) — path to `main.py` changed

If the owner's Windows autostart entry
(`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\"Watch Academy"`)
points at a **source-tree** `main.py` (dev-mode autostart) rather than the
installed `WatchAcademy.exe`, its target path must move from
`...\WatchAcademy\main.py` to `...\WatchAcademy\desktop\main.py` (or the
launcher script that invokes it). If it points at the built `.exe` under
`dist/` or an installed location, PyInstaller's `COLLECT(... name=
'WatchAcademy')` output layout is unaffected by this migration — no change
needed there. Confirm which case applies on the owner's machine before
editing the registry key; do not guess.

## 6. Restart every live watch

After the merge and the two path fixes above, any watch process still
running from the OLD tree layout is running stale code. Quit every running
Watch Academy instance (tray icon → Exit, or `taskkill`) and relaunch from
`desktop/main.py` (source) or the rebuilt `.exe` (installed) so the new
`shared/`-rooted `config.paths.app_root()` takes effect. A watch left
running through the merge will keep resolving `assets/`/`Database/`
relative to its OLD in-memory `app_root()` — harmless (the old files are
untouched until step 2's move deletes them) but stale, and it will start
failing the moment step 2 deletes the old `assets/`/`Database/` trees.
